# M3 Intern Guide

M3 is the operations milestone. It should help maintainers operate the product without cluttering the public commerce UI.

## What belongs in M3

- Operational views
- Admin support surfaces
- Configuration and maintainability improvements
- Internal-only flows that help the team keep the site healthy

## How to think about M3

M3 is not about adding more public pages for the sake of it. It is about making the existing product easier to run, support, and evolve.

## Rules for M3 work

- Keep public and internal responsibilities separate.
- Reuse the public shell only when it is actually appropriate.
- Document operational assumptions so they are not hidden in code.
- Keep warnings, confirmations, and permissions obvious.

## Good M3 habits

1. Confirm whether the screen should even be public.
2. Reuse shared tokens and patterns where the same visual language helps.
3. Keep internal UI clear and low-friction.
4. Write the operational intent down in the issue and the docs.

## What to avoid

- Turning internal tools into public marketing pages
- Copying public-commerce visual patterns without need
- Making operational flows ambiguous
- Skipping documentation because the surface feels “obvious”
