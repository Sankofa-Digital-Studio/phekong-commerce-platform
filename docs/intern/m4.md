# M4 Intern Guide

M4 is the intelligence milestone. It covers reporting, insight, and review-oriented surfaces.

## What M4 is for

- Dashboards
- Insight summaries
- Reporting views
- Review and analysis support for the product team

## Why it needs care

Intelligence surfaces are easy to over-design and easy to over-promise. They should communicate clearly, stay readable, and avoid speculative claims.

## M4 principles

- Make the data easy to scan.
- Keep the layout responsive.
- Use shared chart and table patterns where possible.
- Avoid inventing metrics that are not already defined.
- Make the provenance of data understandable.

## How to approach M4 changes

1. Determine what decision the surface is helping someone make.
2. Identify the smallest useful set of data.
3. Reuse existing components and visual patterns.
4. Add only the interaction necessary to understand the data.
5. Verify that the view still reads well on smaller screens.

## Documentation expectations

- Explain the metric or insight clearly.
- Explain the source of the data.
- Explain any aggregation or filtering.
- Explain what the view is not saying.

## Anti-patterns

- Using visual polish to hide weak data
- Introducing unsupported KPI claims
- Creating a one-off chart style for every page
- Forgetting to explain the meaning of the numbers
