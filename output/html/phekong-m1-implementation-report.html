Executive decision

Proceed with M1 as a public, read-only commerce foundation. Keep checkout, customer authentication, inventory mutation, booking writes, and administrative access in M2 or later. M1 may read active products through the anonymous Supabase client under RLS, with typed fixtures as the deterministic UI and test fallback.

The supplied backlog contains 10 M1 tasks totaling 48 hours. The current repository is a one-page scaffold, but the products read contract and reproducible M0 validation gate are sufficient to start bounded public work.

Three-pass analysis

1Scope and dependencies

M1-06 cites a product schema assigned to M2, while the repo already contains a preliminary products table. Consume it only as an M1 read contract. Do not mark broader M2 work accepted.

Gap: images, categories, service distinctions, and merchandising fields need approval.
2Multi-perspective feasibility

Customers get a coherent journey; design gets reusable tokens; engineering gets an adapter boundary; security keeps public reads isolated; accessibility and operations receive explicit gates.

Gap: brand assets and final content remain external decisions.
3Failure modes

Prevent design-free page multiplication, direct coupling to unstable fields, accidental service-role use, and happy-path-only catalogue claims through contracts and Definition of Done.

Confidence: high for sequence; medium for hosted data and final content.

  components/{layout,marketing,products,ui}/
  lib/products/{types,repository,supabase-repository,fixture-repository}.ts
  lib/supabase/server.ts

Pages consume a ProductRepository, not raw Supabase calls. The live adapter selects approved public fields and filters active products. The fixture adapter supports deterministic tests. Public modules must not instantiate a service-role client.

Definition of Done

  • Approved design or recorded design-not-required decision for every issue.
  • Layouts verified at 320, 375, 768, 1024, and wide desktop widths.
  • Loading, empty, error, and not-found states implemented and tested.
  • Keyboard navigation, visible focus, labels, landmarks, and contrast pass.
  • Products expose no server secret and respect active-product RLS.
  • Metadata, canonical behavior, robots, sitemap, structured data, and image behavior are verified.
  • Lint, type-check, tests, build, and the M0 Supabase wrapper pass.
  • Lead review and conversation resolution complete before merge.
